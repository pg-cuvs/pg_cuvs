# quality-loop 발견 패턴 축적 로그

실행할 때마다 이 파일을 먼저 읽고, 종료 시 신규 패턴을 추가한다.
형식: `- [YYYY-MM-DD] <패턴 요약> — <발견 위치> — <탐지 방법> (재발 N회)`

## 버그 클래스

- [2026-07-28] **shim이 실제 wrapper보다 "친절"해서 호출자 결함을 가린다** — `src/cuvs_wrapper_shim_cpu.c` vs `src/cuvs_wrapper.cu` — 두 파일이 같은 `cuvs_wrapper.h`를 구현하므로 함수별로 (1) 인자 무시 여부 (2) 출력 버퍼 tail 처리 (3) 반환 부호/정렬 규약을 1:1 대조. 이번 패스의 최상위 3건이 전부 이 축이었고 **전부 Tier-1 CI 100% 통과 + Tier-2에서만 발현**. 다음 패스에서도 최우선으로 볼 것.
- [2026-07-28] **한 API의 변종(variant) 간 분기 누락** — `cuvs_wrapper.cu:635` `cuvs_bf_search_filtered`가 `cuvs_bf_search`(574행)에 있는 `impl->precision` 분기를 빠뜨려 float16 인덱스에서 `*nullptr` — 같은 파일 안에서 이름이 유사한 함수쌍(`X` / `X_filtered` / `X_batch`)을 나란히 놓고 가드·분기 목록을 diff. 데몬은 단일 프로세스가 전 백엔드를 서빙하므로 SIGSEGV 하나가 전 세션을 죽인다.
- [2026-07-28] **출력 버퍼 tail 계약 불일치 (미초기화 힙 읽기)** — `pg_cuvs_server.c:2933` `praw = malloc(k)` + wrapper가 `top_k`를 코퍼스 크기로 clamp 후 `[n, k)` 미기록 — 호출자가 `for (i=0;i<k;i++)`로 순회하는데 wrapper가 k개 전부를 채우는지 확인. 쓰레기값이 우연히 유효 범위면 **실재하는 TID가 반환돼 백엔드가 못 거른다**. 주의: 0으로 초기화하면 안 된다(0은 유효 id) — 센티넬 -1이어야 한다.
- [2026-07-28] **base 설치 스크립트만 갱신하고 upgrade 스크립트를 방치** — `sql/pg_cuvs--0.2.0--0.3.0.sql` — `CREATE FUNCTION|VIEW` 이름을 base와 업그레이드 체인에서 각각 뽑아 `comm -23`. 함수 6개 + 뷰 1개가 업그레이드 사용자에게 영원히 누락됐고, 후속 `0.4.0--0.5.0.sql`의 `REVOKE`가 그 함수를 참조해 **`ALTER EXTENSION UPDATE`가 통째로 롤백**. 테스트가 전부 `CREATE EXTENSION`(base) 경로만 타서 37개 회귀 스위트가 전혀 못 잡음.

- [2026-07-29] **계약이 두 조건을 약속했는데 구현은 한 조건만 이행** — `cuvs_wrapper.h:52-58` TAIL CONTRACT는 미충족 슬롯의 사유로 (a) 코퍼스가 top_k보다 작음 (b) **프리필터가 배제함** 둘을 들고 양쪽 다 `CUVS_PAD_ITEM_ID`를 약속한다. `pad_results` 호출 16곳은 전부 (a)뿐 — (b)는 `[0, bk)` 안쪽이라 그 함수가 닿지 않는다. shim은 `shim_topk`가 두 사유를 구분하지 않아 **양쪽 다 이행**하므로 Tier-1에서 표현 자체가 안 된다. 탐지: 계약 문장의 사유를 **절로 쪼개 각각의 이행 코드를 찾아라** — "패딩하는 곳이 있다"로 만족하지 말 것. 수정 `e3e6ca7`(`store_result`).

- [2026-07-29] **나중에 추가된 주 경로가, 테스트가 검증하려던 폴백 경로를 가로챈다** — `infra/scripts/tests/delta-restart-e2e.sh`는 "cagra 인덱스에 INSERT → pending `.delta` 사이드카 생성"을 전제하는데, 3Q EXTEND(`pg_cuvs.c:4110` `cuvs_ipc_extend`)가 들어오면서 **데몬이 살아 있으면 INSERT가 VRAM 그래프를 in-place 갱신하고 그대로 반환**한다. `.delta`는 extend 실패·데몬 다운 시의 폴백으로 격하됐고, 그래서 `ls *.delta`가 빈 손이라 테스트가 2단계에서 죽는다. **기능이 테스트를 무효화했는데 테스트가 실행 불가 상태(유닛 부재)라 아무도 못 봤다** — 두 결함이 서로를 가린 형태다. **탐지법**: 새 주 경로를 추가할 때 기존 경로를 검증하던 테스트를 grep해 그 테스트가 여전히 의도한 분기에 도달하는지 확인하라. 폴백을 테스트하려면 폴백 조건을 강제해야 한다(여기선 데몬을 내리고 INSERT). 30번 항목("폴백 전용 경로는 정상 질의로 도달하지 않는다")과 같은 축의 반대편이다.

## 프로브 선택 (2026-07-28 #101 에서 배운 것)

- [2026-07-28] **결함 클래스에 맞는 프로브를 써라 — 최종 출력은 대개 둔감하다** — #101(힙 오버리드)을 자기 질의 재현율로 판정하려다 두 번 틀렸다. pgvector HNSW 스캔은 **힙 재확인**을 하므로 인덱스에 저장된 벡터가 손상돼도 최종 거리는 테이블에서 다시 계산된다 — 결함본에서도 300/300 통과한다. 메모리 안전성은 ASAN, 계약 위반은 계약값 직접 확인, 정렬 규약은 정답과의 순서 대조. **"질의가 옳은 행을 반환한다"는 오버리드를 무죄로 만들지 않는다.**
- [2026-07-28] **수정 검증도 같은 함정에 빠진다** — `dim` 소스를 바꾼 뒤 옛 소스(`placeholder_dim`) 값을 찍어보고 "수정이 안 먹었나" 오판했다. 계측은 **실제로 쓰이는 값**(`dim_used`)을 찍어야 한다.
- [2026-07-28] **테스트를 넣기 전에 결함을 재도입해 FAIL 하는지 확인하라** — 검출력 없는 테스트를 커밋할 뻔했다. 통과만 보고 넣으면 "테스트가 있다"는 거짓 안심만 남는다.
- [2026-07-29] **단언에 쓰는 관측 지표가 두 상태를 합쳐놓았는지 먼저 확인하라 (거짓 음성)** — fp16 프리필터 검증에서 `pg_stat_gpu_search.search_mode`가 `brute_force`로 나와 "경로에 도달 못 했다"고 판정하고 검증 실패로 결론냈으나 **틀렸다**. 데몬은 BF 프리필터 성공에도 `last_search_mode = 3`을 쓰고(`pg_cuvs_server.c:3001` `used_cagra ? 4 : 3`), 뷰는 3을 D-wedge와 같은 `"brute_force"` 문자열로 렌더링한다(`pg_cuvs.c:5236`). 데몬에 `pret`/`used_cagra`를 직접 찍고서야 경로가 정상 실행됐음이 드러났다. **`cagra_prefilter`만 4로 분리되고 BF 프리필터는 3에 얹힌 비대칭이 원인** — 관측성 결함이지 코드 결함이 아니다. 교훈: "mode를 단언하라"(3O false-done 대책)를 따르더라도, **그 mode 값이 구분하려는 두 경로를 실제로 구분하는지** 매핑 코드를 먼저 읽어라. 지표가 뭉개져 있으면 단언은 거짓 음성을 만든다. 후속: 모드 3 분리(관측성).

## GPU/원격 빌드 함정 (추가)

- [2026-07-28] **rsync 는 mtime 을 보존한다 → make 가 재컴파일을 건너뛴다** — 로컬에서 방금 고친 `.cu` 가 VM 의 기존 `.o` 보다 **오래된** mtime 으로 도착하면 make 가 오브젝트를 최신으로 판단한다. 내용은 새것인데 바이너리는 옛것이고 빌드는 성공한 것처럼 보인다. 동기화 후 `touch <소스>` 하거나 해당 `.o` 를 지울 것. **바이너리에 변경이 실제로 들어갔는지 `grep`/`strings` 로 확인**하지 않았다면 오판했을 상황이다.
- [2026-07-28] **ASAN + CUDA 는 `protect_shadow_gap=0` 없이는 못 뜬다** — ASAN 의 shadow 매핑이 CUDA 드라이버 예약과 충돌해 데몬이 `no CUDA GPUs detected` 로 죽는다. 테스트 시작 전에 죽으므로 결함이 아니라 환경 문제로 오인하기 쉽다.
- [2026-07-28] **CI 의 ASAN 잡은 GPU 경로 결함을 원리적으로 못 잡는다** — `ci.yml` 이 `PGCUVS_CPU_SHIM=1` 로 빌드하므로 shim 에 없는 경로(deserialize/placeholder 등)는 표현 자체가 안 된다. GPU 호스트에서 실제 CUDA 데몬에 ASAN 을 걸어야 한다.
- [2026-07-28] **데몬의 첫 CUDA 컨텍스트 생성 시간은 머신 특성이다** — 한 A100 에서 ~12초, 다른 A100 에서 3분 초과. 고정 `sleep` 은 정상 기동 중인 데몬을 "SOCKET MISSING" 으로 오판한다. 폴링할 것.
