# 조사 skill 관리 기준

skill을 작성·갱신하거나 내용을 분리할 때 적용한다. 내용의 길이보다 어떤 판단에 언제 필요한지로 위치를 정한다.

## 분류

| 위치 | 담을 내용 |
|---|---|
| `SKILL.md` | 적용 조건, 목표, 핵심 흐름, 필수 제약, 상세 참조를 읽을 조건 |
| `references/` | 특정 경계에서만 필요한 절차·기술적 함정·증명 한계 |
| 실행 기록 | 실행 원문, query와 반환값, 당시 수치·식별자·내용 지문·시각·오류 |
| 프로젝트 공통 지침 | 여러 작업에 공통인 판단 원칙과 역할·권한 경계 |

실행 기록은 skill 본문으로 복사하지 않는다. 내부 경로·대화·계정·호스트·세션 식별자와 특정 실행값도 공개 문서에 옮기지 않는다. 재사용 규칙과 사례의 실제 결과를 구분한다.

## 작성과 변경

- 본문만 읽어도 적용 여부와 다음 행동의 선택 기준을 알 수 있게 한다. 핵심 금지·중단 조건을 reference에만 숨기지 않는다.
- reference는 읽는 조건과 존재하는 상대 링크로 연결한다. 필요한 상세만 읽게 하고 링크 목록만으로 본문을 대체하지 않는다.
- 같은 판단의 정본은 한곳에 둔다. 다른 skill·하네스용 사본을 독립적으로 유지하거나 전문을 중복하지 않는다.
- 새 교훈이 이후 행동을 바꾸는지 확인한다. 기존 항목으로 설명되면 통합하고, 반증된 규칙은 고친다. 가설과 일회성 수치를 보편 규칙으로 만들지 않는다.
- 문서 정비는 현재 사용자 권한·수락 조건을 바꾸지 않는다. 새 승인·보고 체계나 별도 운영 프레임워크를 추가하지 않는다.

## 변경 후 확인

핵심 제약·적용 범위·증명 한계가 보존됐는지 확인한다. 상대 링크와 anchor를 검사하고 민감 정보·실행 이력·중복 정본이 섞이지 않았는지 읽는다. 정적 문서 검사의 성공을 모델 행동이나 제품 실행의 검증으로 확대하지 않는다.

검증은 변경 범위에 맞춘다. 문서 정리 때문에 대형 빌드·전체 제품 suite·새 외부 실행을 자동 추가하지 않는다.
