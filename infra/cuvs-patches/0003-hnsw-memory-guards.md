## ABI and budget semantics

No public fields are added. Set the existing `cuvs::neighbors::hnsw::graph_build_params::ace_params::max_host_memory_gb` and `max_gpu_memory_gb` to positive finite GiB values on `hnsw::index_params.graph_build_params`. `hnsw::build` forwards those values to the CAGRA ACE parameters; the disk-backed `from_cagra` serializer reads the same values from the HNSW parameters. Zero keeps the legacy no-limit behavior. Negative, non-finite, non-representable, and overflowing budgets or byte calculations fail before the guarded allocation.

These values bound the source-derived SDK arrays and scratch buffers checked at each phase. They are planned allocation budgets, not process RSS guarantees. Caller-owned input, CUDA/runtime state, allocator-pool residency, fragmentation, and other process allocations remain outside the SDK ledger and require wrapper-side reserve margins.

## Guarded allocations

- ACE uses the final partition count after automatic adjustment to check labels and histogram storage, balanced k-means' source-derived prediction/training scratch, assignment chunks, mappings and offsets, actual histogram-derived maximum subpartition size, optimizer host/GPU workspace, in-memory final graph, and the two reorder buffers per partition. Positive budgets reduce assignment chunk and reorder buffer sizes when possible; an actual imbalanced partition that does not fit is rejected before its dataset allocation. Positive host or GPU budgets use NN-descent for partition builds whose heuristic would select IVF-PQ, because cuVS 26.04's IVF-PQ training/index allocations are data-dependent and outside this bounded ledger. The partition preflight accounts for NN-descent host/GPU workspace and the host kNN graph, then compares the builder peak with optimizer and return peaks before the partition dataset allocation. Zero-budget legacy callers retain the previous builder heuristic.
- Disk HNSW serialization checks the 20-byte-per-row order/reverse-order/level arrays, stream and dummy-index buffers, reserved level metadata, actual hierarchy query vectors and aggregate neighbor matrices, and source-derived NN-descent workspace before allocating the corresponding arrays. With a positive host or GPU budget, upper-level graph construction uses NN-descent so its source allocations can be preflighted; the legacy no-budget path retains the existing IVF-PQ threshold. The batch size is reduced to use the remaining host budget. Row counts beyond the HNSW `int` ID range and random hierarchies above the supported 64-level bound fail before the corresponding array allocations.
- The guarded path does not allocate a full `N x D` dataset copy.

- `test/native/hnsw-sdk/guard_memory_budget.cpp` is a standalone CPU fixture for checked arithmetic, GiB conversion, serializer array sizing, NN-descent workspace sizing, and reorder-buffer minimums.

It exercises separate host-budget and GPU-budget rejection cases, then a successful bounded ACE disk build on a skewed dataset. Supply a persistent disk root; the worker did not run the GPU fixture or native SDK build.
